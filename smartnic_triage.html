STANDARD OPERATING PROCEDURE

GPUv6 SmartNIC Connectivity

Triage and recovery procedure for DO tickets reporting SmartNIC connectivity issues on GPUv6 hosts. Applies the least-disruptive validation path before executing hardware intervention.

Safe Operating Rule: Do not power-cycle or restart a healthy host just to test connectivity. The host must remain powered ON for standard presence, port, and DHCP validation. Power OFF only if SPI diagnostic boot (Elba-Gold / halctl) is explicitly required.

1. Signal Meaning & Quick Action

Evaluate current output signals against target actions.

Signal / State Meaning Required Next Action
Present=Yes, Pool_Ready=Yes Card visible, healthy, & provisioned. Only validate physical port & DHCP if error logs indicate pending failure.
Admin UP / Oper UP SmartNIC & far-end ToR physical link up. Run dhclient and validate identity against deployment plan.
Admin UP / Oper DOWN (>5m) Interface enabled; no physical link detected. Validate planned ToR port, optical levels (RX), transceiver seating, and fiber patch.
No DHCPOFFERS received DHCP broadcast received no response. Verify link training, ToR port configuration, and VLAN assignment before changing state.
No Elba-Gold / halctl down Card is not in diagnostic boot image. Run the controlled SPI-boot recovery flow (Step 3).

2. Procedure Steps

Follow systematically; record all initial evidence and state changes in the ticket.

Step 1 — Evidence Collection

Capture Baseline Before Changing State

In Monocle/HoPS, copy error codes, descriptions, and console dumps into ticket. In HoPS CLI & ILOM, record planned identity:

smartnic_info
smartnic_presence
show /System power_state
show /System/Open_Problems

Note: Do not run fmadm repair allfaults as a routine action. Repair only known stale faults.

Step 2 — Normal Path

Validate Presence with Host Powered On

If the host is off, start it and wait for SmartNICs to initialize. Then re-verify presence:

start /SYS
smartnic_presence

Decision: If both cards show Present=Yes and Pool_Ready=Yes and the issue is resolved, document and close. If a card is missing, not ready, or shell is down, proceed to Step 3.

Step 3 — Controlled Recovery

SPI-Boot Diagnostic Recovery (Affected Slot Only)

Slot 10 = RoT 1 | Slot 11 = RoT 2. Power host off, enable SPI boot, start host, then immediately clear the SPI flag:

sp_exec stop -script /System
rot_smartnic_spiboot slot=10 enable=true
sp_exec start -script /System
rot_smartnic_spiboot slot=10 enable=false
connect_rot3 1   # Slot 10 (use 2 for Slot 11)

If diagnostic login still fails, mark ticket Pending Engineering and raise a CRDMGMT ticket.

Step 4 — SmartNIC Shell

Port Configuration & DHCP Validation

Check link state. If administratively down, force 200G speed and enable port Eth1/1 (or Eth1/2 if plan specifies):

halctl show port status
halctl debug port --port Eth1/1 --auto-neg disable --speed 200g --fec-type none --admin-state up
halctl show port status
dhclient -v inb_mnic0; echo; fwenv -p serial

If fwenv yields defaults, inspect cat /tmp/fru.json. Record bound IP and SmartNIC serial.

Step 5 — Verification

Plan Cross-Check & Fault Isolation

Compare bound IP and serial against target plan:

get_plan_ports name=<SmartNIC-DNS>

Identify expected ToR and peer interfaces prior to any physical cable move or port bounce.

3. Fault Isolation Guide

Actions to take based on post-DHCP observations.

Observation Resolution / Action
UP/UP, DHCPACK, IP matches plan Run smartnic_presence. If cards are Present=Yes, Pool_Ready=Yes, resolve ticket for provisioning.
UP/UP, but no DHCP offer Validate expected ToR interface and DHCP/VLAN profile with network team. Escalate with serial, expected IP, and ToR port.
UP/DOWN for >5 minutes Inspect ToR port status, transceiver seating, and fiber patch path.
ToR shows notconnect, RX is -30.00 dBm No optical light. Set ticket to Pending Engineering, execute LC-cleaning/VFL test, and replace cable via change process.
IP / Serial swapped with other card Correct cabling swap. Bounce link, wait 30s, re-enable, and test DHCP: 
halctl debug port --port Eth1/1 --admin-state down
# Wait 30s
halctl debug port --port Eth1/1 --auto-neg disable --speed 200g --fec-type none --admin-state up
dhclient -v inb_mnic0; echo; fwenv -p serial

4. Quick Command Card

High-frequency commands formatted for quick copying.

Health & Baseline

smartnic_info
smartnic_presence
show /System power_state
show /System/Open_Problems

Checks presence, card IDs, power, and active ILOM faults.

RoT Console Access

connect_rot3 1   # Slot 10
connect_rot3 2   # Slot 11

Direct console session into the Elba-Gold environment.

Controlled SPI Recovery

sp_exec stop -script /System
rot_smartnic_spiboot slot=10 enable=true
sp_exec start -script /System
rot_smartnic_spiboot slot=10 enable=false

One-time recovery sequence. Replace 10 with 11 for Slot 11.

Link & DHCP Validation

halctl show port status
halctl debug port --port Eth1/1 --auto-neg disable --speed 200g --fec-type none --admin-state up
dhclient -v inb_mnic0; echo; fwenv -p serial

Configures port params and pulls dynamic host IP.

Closure Checklist: Ensure both cards show Present=Yes/Pool_Ready=Yes, link is Oper UP, and DHCPACK matches plan.
